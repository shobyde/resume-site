This Week in Agents: Three Active Parameters

Three releases this week moved the agent stack toward things you can actually run: an image generator with 3B active parameters, a text model trained to fit a quantization target, and a front end reduced to a single HTML file.

NVIDIA open-weighted a 3B-active image generator

Nemotron-Labs-Image-30B-A3B is a 30B MoE that activates 3B parameters per token, and it generates images autoregressively: discrete visual tokens from a 196,560-entry codebook, decoded to pixels by a separate 642M tokenizer. Any resolution that is a multiple of 16 works, which is a nicer contract for downstream pipelines than most diffusion models offer. The official benchmarks are strong (GenEval 92.86, per the ComfyUI wiki writeup), but Wccftech's account notes GPT Image 2 still leads on GenEval2 and Qwen-Image-Bench, so the "outpaces GPT Image 2" headline deserves its qualifier. The license is non-commercial, which I suspect will matter more than the benchmark deltas. The interesting part for me is architectural: image generation as next-token prediction with a fixed token budget of 4,352 per image turns generation into a decoding-cost problem, and MoE sparsity is exactly the tool for that.

Baidu shipped an intermediate checkpoint as a product

ERNIE 5.5 Flash Preview is a 280B/14B-active MoE with 1M context, and the model card is unusually honest about what it is: an intermediate checkpoint from post-training, released so users can shape the final version. It is trained quantization-aware (MXFP4 experts, W4A8), which means the released weights deploy at 4-bit without a calibration pass, and a DSpark draft head gets speculative decoding to an acceptance length above 5.5 tokens. The reported agent-benchmark scores are competitive but not leading: Terminal-Bench 4.0 at 46.5 against Claude Opus 5.5's 66.4, by Baidu's own evaluation table. I would rather have a self-described imperfect checkpoint with documented gaps than a polished release that hides them, and publishing mid-training state is a genuinely new move for a lab of this size. The uncomfortable question is how much the quantization-aware training cost: the card says accuracy is unaffected, but there is no comparison against the same model trained without it.

Nemilia: a multi-agent workspace in one HTML file

Nemilia is a drag-and-drop agent pipeline builder with MCP tool calls and client-side RAG, all in a single HTML file with no backend and no build step. It is a small project: the Show HN sat at 2 points and drew no discussion when I checked. I still kept it, because it is a working demonstration of how little infrastructure the agent-loop pattern actually needs once WebGPU inference runs in the browser. The pieces that used to justify a backend service, tool dispatch, state machines, human checkpoints, now compile to client-side code. That is not a prediction that server-side agent runtimes go away; local models trail hosted ones badly enough that serious work still runs remotely. But a single-file reference implementation is the fastest way to learn what a runtime is actually doing, and it makes a good check on whatever enterprise agent platform you are being sold.

The common thread is shrinking the trusted footprint: fewer active parameters, a checkpoint that tells you what it is, a runtime you can open in a text editor.

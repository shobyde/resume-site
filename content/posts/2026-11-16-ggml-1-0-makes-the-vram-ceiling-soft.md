# ggml 1.0 Makes the VRAM Ceiling Soft
Tag: tools
Subtitle: MoE models that slightly exceed VRAM no longer fail to load, because ggml v1.0 can cache the less-used experts in host RAM.
---
ggml hitting 1.0 is a milestone worth marking, but the feature that matters to me is MoE expert caching in host RAM. The headline numbers in the release are FP8 support, YaRN truncation controls, and FlashAttention across CUDA, Metal, Vulkan, OpenCL, SYCL, and WebGPU. Those are real, but they are the kind of feature list that gets announced. The expert-caching change is different: it removes a hard failure mode. Before this, a model whose expert weights slightly exceeded VRAM either failed to load or forced a swap that destroyed throughput. Now the slow experts move to host RAM and the hot ones stay on the device. That is a graceful degradation path, and it changes how I size local models. I used to treat VRAM as a hard ceiling and shop for smaller quantizations. Now the ceiling is soft, and the question becomes which experts are actually hot for my workload, which is a measurement I do not currently have. The honest caveat: caching less-used experts in host RAM only helps if the routing is skewed enough that most tokens hit a small subset. For a model with uniform routing the cache thrashes and you are worse off than just picking a smaller model. I have not measured this, and the release does not give numbers. So my takeaway is conditional. If the routing is skewed, this is the most practical local-inference change in a while. If it is not, it is a feature that looks good in a changelog. Worth a benchmark before I trust it.

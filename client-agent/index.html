The trade most assistants make

A model in the tab costs a download, a GPU, and the truth.

Shipping an assistant usually means shipping weights: hundreds of megabytes, a WebGPU requirement, and an answer nobody can check. On a phone with metered data, or a work laptop with the CDN blocked, the assistant is a spinner.

client-agent takes the other position. The app publishes what it can do and what it knows. The library retrieves, joins and composes. When the facts run out, it reads the page it is standing on. Every reply can be traced to the rows that produced it.

Anatomy

One turn, five steps, no inference server.

Capabilities are declared beside the feature that owns them

A build step extracts them with the TypeScript AST into one manifest: routes, actions, queries, and prose knowledge.

The question is ranked against that manifest

BM25 over titles, keywords and descriptions. Twenty-two capabilities take about three microseconds, which is why retrieval is not the thing the visitor waits for.

If the answer needs live data, the engine calls the app

A rule declares the tools it needs. The runtime runs one, hands back the structured result, and the engine turns it into facts for this turn.

Rules join the question to the facts

A small Datalog subset: joins, scoped assumptions, a depth cap. projects_using(?P) :- uses(?P, ?T), asked(?T).

The sentence is composed, then streamed with its trace

The app writes the words, the library streams them, and the steps it took stay on screen above the answer.

src/agent/assistant.jsthe rule
// The app's half: which tool, and how a solution becomes a sentence.
{
  id: 'projects.using',
  title: 'Which projects use a technology',
  keywords: ['which projects use', 'built with'],
  goal: 'projects_using(?P)',
  steps: [{
    capabilityId: 'projects.list',
    toFacts: (result) => result.projects.flatMap((p) => [
      fact('project', slug(p.title), p.title),
      ...p.stack.map((t) => fact('uses', slug(p.title), t)),
    ]),
  }],
  compose: ({ solutions }) => `${solutions.length} projects use it.`,
}

A2UI

The interface assembles itself, and the page keeps its design system.

A handler can return a declarative surface instead of prose: a stream of components, bindings and data. The agent never touches the DOM. The host renders the surface with its own buttons, its own type, its own spacing, so an answer that is a card looks like every other card on the site.

About the timings. Compute is measured on the production bundle in this browser. The lead-in is presentation, not work: a reply is finished in milliseconds, so the pause exists to make the reasoning legible, and it is skipped when the tab is hidden.

Honesty

What it will not do.

ParaphraseAnswers are composed from declared text and data. It will not invent a sentence about something nobody wrote down.
World knowledgeAsk about the weather and it has nothing. The knowledge base is the app's, not the internet's.
Open-ended opinions"Why should I hire him" gets facts and a deflection, because a judgement is yours to make.
Rules you did not writeCoverage is the work. Every new question shape is a rule, a fact, or a scan, and that is the point.
